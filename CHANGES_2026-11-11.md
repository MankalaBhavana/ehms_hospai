# EHMS change list and deployment notes (release 2026-11-12)

Scope: application code only. Nothing here touches nginx, Cloudflare, Docker/compose, ports, `TRUST_PROXY`,
`deploy/` or `prod.mjs` routing.

## Deploy steps
1. Copy the files in this package over the tree at the same paths.
2. Backend: `pip install -r backend/backend/requirements.txt` (versions are now pinned; see Risks), restart the API.
   No manual migration: the two new insurance tables are created automatically on first use
   (`CREATE TABLE IF NOT EXISTS`), and the `doctors.user_id` column is added at start-up.
3. Frontend: `cd frontend && npm ci && npm run build`, restart the web server.
4. Smoke test: sign in, create a doctor (with a password) and log in as them, register an ER patient
   (bill appears with the consultation fee), open an insurance case, open a report.
5. Change the initial administrator password immediately after first sign-in.

## What changed
### Security / dependencies
- Reports: report type is looked up in a fixed map; never used as a table name (SQL-injection fix). Unknown type -> 400.
- Doctor login lookup no longer compares a doctor code with an integer id column.
- `requirements.txt` split (core / ai / dev) and pinned to versions with no known CVEs (Pillow 13.0.0, flask-cors 6.0.0,
  Flask 3.1.3, pypdf 6.21.4, pyasn1 0.6.5, cryptography 50.0.0, fpdf2 2.8.8, faster-whisper 1.2.1). npm audit: 0 issues.
- CI workflow added (`.github/workflows/ci.yml`): backend tests, frontend build, insurance tests; typecheck advisory.

### Doctors and users
- No default password. A doctor created without a password gets an inactive login; the form now requires 8+ characters.
- PUT on a missing doctor returns 404 (does not create). Doctor and login linked by `doctors.user_id`.
- Re-creating a deleted doctor reactivates the same login with the new password; username is normalised, email validated.
- Errors: 409 duplicate / 400 input / 500 server, logged with a `request_id`; the UI shows the server message.
- User-save double submit guarded (was the double `users/create`).

### Billing
- ER: a new ER visit opens a running ER bill at registration with the consultation fee (doctor master fee, else Rs 100).
  One ER bill per patient per day (local, dispatched and server invoice are merged).
- OP: a visit appears in OP billing only once an appointment exists (doctor assigned) or the consultation is complete.
  Registration no longer marks the appointment checked-in; "Issue token" requires a booked appointment (emergency priority excepted).
- Duplicates: invoice creation is idempotent (same patient/module/amount/visit within 60 s returns the existing invoice);
  the counter shows identical server invoices once.
- Bill search no longer crashes on bills with missing fields.
- Patient clinical report: billing section is built from the real bill (itemised, paid, balance, receipts); fabricated
  medicines, tests, phone, address and bed charges removed.

### Insurance
- State machine tightened: no skipping eligibility, no pre-auth approval before submission, rejected pre-auth is revised
  and resubmitted, claim decisions have one path (always creates the settlement record), no forced statuses.
- Fabricated insurer "inbound email" and fake policy number removed; case header shows real patient data.
- "Amounts at a glance" ledger on the case page (requested, authorised, billed, claimed, sanctioned, deductions,
  received, patient payable, outstanding).
- Fixed: a patient sent to insurance from billing showed Eligibility / Pre-Authorization / Treatment as "Completed".
  The billing hand-over used to force the case to "Final bill ready" from any earlier step, and the stepper marked
  every earlier step done by position. Now: the hand-over only advances a case that is at discharge (otherwise it is
  noted once and the case stays put); billing cannot hand a bill to insurance until the case is at discharge; a new case
  from a bill starts at Eligibility; the stepper shows a step as completed only when its work is on record
  (otherwise "Not completed"); cases already pushed ahead with no eligibility/pre-auth are corrected automatically
  (audit entry "Status corrected").
- Menu ordered by the patient journey; Insurance Reports added.
- PostgreSQL backend: `/api/insurance/<collection>` (cases, insurers, tpas, packages, document rules, pricing rules,
  patient policies, fixed package bills). Tenant-scoped, versioned (409 on stale save), audited (`insurance_audit_logs`),
  cases cannot be deleted. Frontend syncs after sign-in and every 30 s; an empty server is seeded once from the browser.
- Reimbursement workflow: choose Cashless or Reimbursement; patient payments and receipts; printable claim pack;
  claim blocked until the patient has paid and the pack exists; insurer payment recorded as paid to the patient.
- Tests: `npm run test:insurance` (29 steps) and `npm run test:insurance:sync` (8 steps).

### Insurance: mailbox, guide, printing
- Hospital mailbox (new): `/api/insurance-mail/*`. Link the desk's email (SMTP send, IMAP replies) in Email Hub -> Mailbox,
  with Test connection. Sends from the application with real attachments and the claim tag `[CLM-...]` in the subject;
  "Check mailbox for replies" reads the inbox read-only (BODY.PEEK) and keeps ONLY messages carrying a case tag or
  replying to a mail we sent. Password stored encrypted (Fernet, key derived from SESSION_PEPPER: changing the pepper
  means re-entering the mailbox password). New tables `insurance_mail_settings`, `insurance_mails` (auto-created).
  Without a linked mailbox the email button says "(record only)" instead of pretending to send.
- Removed fake behaviour in the Email Hub: the "Live TPA Gateway" badge, the "2 new decisions fetched" toast, the
  generated random approval code default.
- Insurance -> Setup is one page with three tabs: Main setup (insurers, TPAs, packages, pricing, document rules), Mail setup and the Step-by-step plan. Mail setup has with a 5-step explanation, quick-fill for Gmail /
  Microsoft 365 / Zoho, Test connection and an optional "send a test email to" address.
- Step-by-Step Plan (Insurance -> Step-by-Step Plan): the full procedure as ~30 small steps over the 8 stages, each with
  what / why / click-by-click how / who / where and a button to the right screen. Pick a patient and every step is ticked
  from that case's real records (policy, documents verified, eligibility recorded, mails sent, queries answered, payment
  received...), the next action is highlighted and a progress bar shows the case. Reimbursement cases skip the pre-auth
  steps. With no patient selected it shows the whole procedure plus the live number of cases at each stage.
  Covered by the flow test (finished cases have no open step; a new case shows eligibility as the work to do).
- In-app guide: Insurance -> "How to use Insurance" (now the fourth tab of Insurance -> Setup; stages, cashless, reimbursement, mailbox, amounts, daily routine,
  roles, printing, common messages). Stage text comes from the same source as the case screens.
- Printing: case summary is a clean A4 sheet; pre-auth form prints all 4 pages; other insurance prints show only the
  document (no menus/buttons/cut-off scroll areas) via `utils/insurancePrint.ts`.
- Untested against a real mail provider: SMTP send was verified against a local test server and inbound matching by
  unit tests; the IMAP network read could not be tested here. Test with the desk's real mailbox on staging.

- Pre-auth screen: the "Pre-Authorization Form Template" dropdown listed eight made-up templates with invented form codes,
  and choosing one changed nothing. Replaced by a plain description of the one real form and the insurer's own form code
  (set in Masters); the fake template choice was removed from Masters too; hardcoded fallback codes removed.

### Billing detail, bed rates, IP bills, transfers
- Receipts: bill lines printed as "SUR100 Charge". The frontend sent invoice lines to the server with the wrong field
  names (service_name/amount/department instead of description/category/total), so the server stored lines with no
  description. Fixed at the source; the server also accepts the old names; a server invoice with blank lines now falls back to
  the itemised local bill; the receipt shows what each charge is (category, who ordered it, when).
- Beds: no built-in room rate. Adding beds requires a daily rate typed by the user (server rejects a missing/zero rate);
  the form no longer pre-fills it from the bed type or ward; cards show "Rate not set" instead of an invented figure;
  the IP bill no longer falls back to Rs 2000/5500 per day. Nursing (Rs 600/day) and doctor-rounds (Rs 1000/day) lines that were
  added to every IP bill automatically are REMOVED (also from existing bills): an inpatient stay is billed at the bed's own
  assigned daily rate; other charges appear only when really charged. IP bills no longer invent age 42 / phone numbers.
  The bed card shows the real amount: "Due Rs X" for self-pay; for insured "Insurer Rs X" + "Patient Rs 0".
- IP billing shows the patient's full name (it used the first name only).
- Insured admissions: the patient's own bill is Rs 0 from the start (no payment is asked); the insurance record carries the
  complete amount with every itemised line (bed, lab, radiology, pharmacy...). A co-pay / non-payable split set by hand at
  hand-over is respected. The receipt shows "Covered by insurance" and "Patient payable".
- Transfers: when a patient is moved to another department (OP department transfer, bed-to-bed, ER to ward), a notice is
  stored on the server (`transfer_notices`) and the receiving department sees it in the bell (badge shows without opening),
  with the patient, from/to and a link to the right screen; seen per user. Only people who can open that department see it.

- ER bed charge (new): every ER visit has a "Bed & Charge" tab: the desk types the ER bed/bay, the charge per day and the
  number of days; it becomes one "ER bed" line on that patient's ER bill (saving again replaces it). No rate is pre-filled.
  A reminder strip shows on any open ER visit that has no bed charge. Sending the ER bill to billing now keeps what is
  already on the bill (it used to rebuild the bill and could wipe the consultation / bed lines) and no longer injects
  built-in "triage Rs 250 / nursing Rs 50" lines when nothing was charted. The ER consultation fee is the assigned
  doctor's master fee only (no Rs 100 fallback); the close dialog's fee box starts empty.

- Bed card "Due": a patient moved to another bed was billed for the NEW bed from the original admission date (days counted
  twice: the earlier bed already had its own invoice). Days now run from when the current bed was allocated. The card's
  Due is the stay's whole unpaid bill (earlier bed invoice + current bed), and hovering shows each line it is made of.
  Old built-in nursing/rounds lines are cleaned from existing bills.

- Bed charge flip-flop (major): right after a refresh a bed showed its true amount (e.g. Rs 100); once the server data
  arrived the same stay was counted TWICE (the browser's bill line and the server's "room charges so far" line did not
  match, so both were kept: 100 became 200 and kept growing), and a refresh brought the lower number back. Both lines now carry
  the same code and merge into one. Covered by `npm run test:billing` (before sync, after sync, second sync: same amount).
- ER "More" menu opened under the sidebar with cut-off labels; it is now placed from the button's real position, kept inside
  the window, and its labels wrap.

- ER billing flow: the ER visit shows the complete amount (consultation + the bed charge entered on the visit + treatments
  and investigations) as "ER bill total ... not sent to billing yet", and the button reads "Send to Billing - Rs X".
  The bill reaches the billing counter only when that button is pressed (new field `erSentToBilling`); before, the
  running bill was on the counter from registration and the header already claimed "Sent to Billing". ER visits created
  before this change keep their current behaviour.

- ER charges come only from the hospital's own data. Charting used to add charges from a built-in rate card and "Send to Billing"
  injected default lines (triage Rs 250, nursing Rs 50). Now ER medicines are picked from the pharmacy's stock (name, strength, MRP, units
  in stock; out-of-stock or unlisted medicines are refused) and billed at pharmacy MRP x quantity; lab/radiology tests are billed at the
  diagnostic tariff price; the bed and anything else (procedures included) are typed under ER -> "Bed & Charges" (removable). The ER
  header total and "Send to Billing" count exactly the lines on the bill, then send it to billing. Local mock close no longer adds Rs 100 / Rs 40.
  Tests: unknown medicine = no price/no charge; pharmacy medicine shows MRP and stock, 3 x Rs 40 = Rs 120 added, removable.

### Speed
- The app shipped as ONE 9.0 MB script that every user downloaded and parsed before seeing anything. Pages now load on
  demand (72 page components are lazy): the first-load script is 2.6 MB (about 1 MB compressed), pages download the first
  time they are opened, and the busiest ones (registration, OP, queue, billing, ER, inpatient, doctor, pharmacy, lab,
  radiology) are fetched in the background right after sign-in so the first click is instant.
- Insurance sync: eight requests per refresh became one `/api/insurance/snapshot`; when nothing changed the reply is
  35 bytes (etag), and polling stops while the browser tab is hidden. Same for the billing poll.
- Measured: API calls answer in 4-20 ms on the server. `npm run bench` times the claim lookups (about 25 ms per call at 400 bills
  + 400 OP visits, growing faster than linearly); callers that run it on every render are the next thing to optimise.
- Ops note (not changed here): serve `/assets` with gzip or brotli at nginx; the Node server sends them uncompressed.

### Frontend
- Doctor list synced once per sign-in and only for admin roles; ER/bed badge polling only for roles that can open them.
- HR core calls use the shared API helper (CSRF + errors). Hardcoded biometric / analyzer IPs and serials removed.
- Radiology print: one shared, clean A4 layout (letterhead, patient grid, findings, impression, signatures, repeating header/footer),
  no fabricated accession / receipt / registration numbers.
